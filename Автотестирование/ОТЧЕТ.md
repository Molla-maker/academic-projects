# Отчёт по лабораторной работе «Заказ доставки»

## 1. Описание приложения

Приложение «Заказ доставки» предназначено для оформления заказа на доставку. Реализовано в виде веб‑приложения (HTML, CSS, JavaScript).

### Поля ввода

| № | Поле            | Описание                                  |
|---|-----------------|-------------------------------------------|
| 1 | Адрес доставки  | Текстовое поле для ввода адреса          |
| 2 | Время доставки  | Поле для ввода времени в формате ЧЧ:ММ   |
| 3 | Товары          | Список товаров через запятую             |
| 4 | Сумма заказа    | Сумма в рублях                           |
| 5 | Комментарий     | Дополнительные пожелания (необязательно) |

### Кнопки

- **Ок** — проверка данных и вывод результата
- **Отмена** — очистка всех полей ввода

---

## 2. Правила валидации (корректные данные)

| Поле              | Допустимые значения | Ограничения                                                                 |
|-------------------|---------------------|----------------------------------------------------------------------------|
| **Адрес доставки**| Строка             | 5–200 символов, обязательное поле. Пробелы в начале и конце обрезаются    |
| **Время доставки**| Время              | Формат ЧЧ:ММ. Часы: 0–23, минуты: 0–59. Обязательное поле                  |
| **Товары**        | Строка             | Минимум 1 товар, разделитель — запятая. Пустые элементы игнорируются      |
| **Сумма заказа**  | Целое число        | 100–100 000 рублей. Только целые числа без дробной части. Обязательное    |
| **Комментарий**   | Строка             | Необязательное поле. Если указан — не более 500 символов                  |

### Примеры корректных данных

- Адрес: `ул. Ленина, д. 10, кв. 5`
- Время: `14:30`, `00:00`, `23:59`
- Товары: `Хлеб`, `Молоко, Сыр, Масло`
- Сумма: `100`, `1500`, `100000`
- Комментарий: пусто или текст до 500 символов

## 3. Намеренные ошибки валидации (баги)

Для демонстрации работы тестов в приложение намеренно внесены ошибки:

### Баг 1: Поле «Время доставки»

- **Описание:** при проверке минут используется условие `minutes > 60` вместо `minutes >= 60`
- **Следствие:** время `14:60` (некорректное) проходит валидацию и даёт «Успешно»
- **Корректное поведение:** допустимый диапазон минут 0–59, значение 60 должно отклоняться

### Баг 2: Поле «Сумма заказа»

- **Описание:** при проверке минимума используется условие `sum < 99` вместо `sum < 100`
- **Следствие:** сумма `99` (ниже минимального порога) проходит валидацию и даёт «Успешно»
- **Корректное поведение:** минимальное значение суммы — 100, 99 должно отклоняться

## 5. Автоматизированные тесты

Реализовано **20 автотестов**, проверяющих основные и дополнительные сценарии работы формы.

Автотесты реализованы в одном варианте:

1. **HTML‑раннер (без установки ПО)** — файл `tests/run_tests.html`, выполняемый прямо в браузере.

### Покрытие тестами

- 10 автотестов повторяют сценарии ручных тест‑кейсов (например: успешный заказ, пустой адрес, пустые товары, сумма ниже минимума, некорректное время и т.д.).
- 10 автотестов проверяют дополнительные сценарии и граничные случаи, отличающиеся от ручных тестов.

Примеры уникальных сценариев автотестов:

| №  | Сценарий                                     | Описание                                                     |
|----|----------------------------------------------|--------------------------------------------------------------|
| 1  | Адрес только из пробелов                    | После `trim` адрес пустой — ожидается ошибка по адресу      |
| 2  | Отрицательная сумма                          | Сумма `< 0` — ошибка по сумме                               |
| 3  | Сумма равна нулю                             | 0 рублей — ошибка по сумме                                  |
| 4  | Адрес ровно 5 символов                       | Граничное значение длины адреса, должно приниматься         |
| 5  | Время `24:00`                                | Недопустимое значение часов — ошибка по времени             |
| 6  | Сумма `100001`                               | Значение выше максимума — ошибка по сумме                   |
| 7  | Время `14:60`                                | **Невалидно, но проходит** из‑за намеренного бага           |
| 8  | Сумма `99`                                   | **Невалидна, но проходит** из‑за намеренного бага           |
| 9  | Несколько товаров с пробелами после запятых | Корректная обработка списка товаров                         |
| 10 | Пустое поле времени                          | Время не задано — ошибка по времени                         |

## 6. Запуск автотестов

### Вариант 1 — HTML (без установок, рекомендуется)

1. Открыть в браузере файл  
   `tests/run_tests.html` (двойной клик по файлу).
2. Нажать кнопку **«Запустить тесты»**.
3. На странице отобразится список из 20 тестов:
   - зелёные строки — тест пройден;
   - красные строки — тест провален.
4. Внизу выводится сводка: количество пройденных/проваленных тестов.

Этот вариант не требует установки Node.js и дополнительных библиотек — достаточно любого современного браузера.

## 9. Запуск приложения

Для запуска самого приложения достаточно:

1. Открыть файл `index.html` в браузере (двойной клик или через «Открыть с помощью…»).
